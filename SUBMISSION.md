# Загрузка решения — готовые ответы для формы

Задача: «Предиктор изменений в графике транспорта»

---

## 1. Ссылка на рабочую систему из 3 модулей (ML-ядро + Backend + BI-дашборд) в Docker, запускаемая по README

```
https://github.com/vikt-sav/mt-hack-team-entropy
```
Запуск: `docker compose up --build` (README, раздел «Запуск»). Дашборд:
http://localhost:8000/dashboard/index.html — карта маршрутной сети (нитки по улицам
OSM, остановки), ТС-стрелки по курсу с цветовым риском (зелёный/жёлтый/красный),
панель алертов-инцидентов (прогноз опоздания, причина, участок застревания,
рекомендация), What-if и чат диспетчера в карточке ТС. Поток телеметрии NDTP
поднимается автоматически (сервис `replay`: исторический датасет → живой поток,
окно 07:20–11:20, ×30). Подача потока штатным эмулятором организаторов:
`docker load -i ndtp-telemetry-emulator.tar`, затем `POST /api/start` с
`unitId` из столбца `unit_id` файла `traffic.csv` (система свяжет юнит с ТС и
расписанием; время пакетов выравнивается автоматически). Живой стенд (без
установки): https://mt-hackathon-team-entropy.cloudpub.ru/dashboard/index.html

Модули: **ml-core** (:9201 NDTP-сервер, :8100 инференс CatBoost), **backend**
(:8000 FastAPI, API + WebSocket), **dashboard** (статика, MapLibre).

## 2. Ссылка на инструкцию для жюри (как подать поток / где прогнозы и алерты / как открыть дашборд и метрики)

```
https://github.com/vikt-sav/mt-hack-team-entropy#инструкция-для-жюри
```

Кратко: `docker compose up --build` → открыть http://localhost:8000/dashboard/index.html
(карта, ТС-стрелки, алерты-инциденты слева, What-if, чат в карточке ТС; обновление
в реальном времени по WebSocket). Поток подаётся сам (replay); альтернативы — живой
эмулятор организаторов NDTP (команда в разделе «Запуск») или второй replay с другим

Метрики: `python tools/stream_eval.py --split test` (MAE в потоке 42.2 с),
`python tools/bench_latency.py` (latency инференса). Надёжность: остановите replay —
система живёт на последних данных; запустите — восстанавливается.

## 4. Описание сведений о производительности и список реализованных дополнительных возможностей

**Производительность** (`tools/bench_latency.py`, CPU): инференс CatBoost —
**8.7 мс на ТС** (p95 13.1 мс), полный цикл парка — **88 мс** (p95 92.6) при лимите
1–2 с; очередь не накапливается (WS-пуш каждые 2 с); холодный старт — секунды
(компактный кэш OSM-графа ~1.3 с); обрывы потока — деградация без падения
(работа на последнем известном состоянии, автопереподключение replay/эмулятора).
ONNX-инференс деплой-модели: 0.63 мс одиночный (7.7× быстрее нативного), эквивалентность
предиктов 1.7e-4.

**Дополнительные возможности (все пункты ТЗ):**
1. **Map Matching по OSM** — нитки маршрутов по реальным улицам (граф ~1 млн узлов,
   Overpass) + HMM-матчинг телеметрии (leuvenmapmatching): уточнённые оценки
   отклонений и «участок застревания» в карточке инцидента;
2. **What-if анализ** — выпуск резервных ТС (сжатие интервала → снятие до 35 %
   bunching-части прогноза) и сокращение стоянок (сек × остановок впереди), сценарий
   per-vehicle и агрегат по парку;
3. **Оптимизация инференса** — ONNX-экспорт деплой-модели с числовым кодированием
   категорий;
4. **Ансамбль CatBoost + PyTorch GRU** — полный контур обучения последовательностей
   телеметрии; грид-поиск веса бленда выбрал чистый CatBoost (решение данными).

**Сверх ТЗ:** стрелки ТС по курсу с плавным движением (интерполяция + инерция),
остановки на линиях с адресами, чат «диспетчер → водитель» в карточке ТС, GPS-гигиена
телеметрии (телепорты датасета отфильтрованы), деградация подложки карты при
блокировке CDN, real-time WebSocket-обновления.
