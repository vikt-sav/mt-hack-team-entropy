# Хакатон Московского транспорта

**Трек:** «Предиктор изменений в графике движения городского транспорта»
**Команда:** «Энтропия»

ИИ-система проактивного управления наземным транспортом: потоковая телеметрия NDTP →
ML-прогноз задержки за 10–15 минут до события → алерты и What-if на дашборде диспетчера.

**Скор Data Science: 1.0 / 1.0** (MAE 40.9 с против baseline 93.4 с).

## Запуск (Docker, одна команда)

```bash
docker compose up --build
```

- **Живой стенд:** https://mt-hackathon-team-entropy.cloudpub.ru/dashboard/index.html —
  уже работает, установка не требуется;
- **Дашборд:** http://localhost:8000/dashboard/index.html
- **Swagger:** http://localhost:8000/docs (backend), http://localhost:8100/docs (ml-core)
- **Поток:** сервис `replay` стартует сам — исторический датасет превращается в живой
  NDTP-поток (окно 07:20–11:20, ×30, цикл 8 минут); скорость — `REPLAY_SPEED` в
  docker-compose. Живой эмулятор организаторов: `docker load -i
  ИТОГОВЫЕ_ТРЕБОВАНИЯ/dataset/ndtp-telemetry-emulator.tar`, затем
  `curl -X POST http://localhost:8080/api/start -d '{"targetHost":"host.docker.internal","targetPort":9201,"units":[{"unitId":1166336,"intervalMs":5000,"autoGenerate":true,"cells":[]}]}'`
- **Проверка метрик:** `python tools/stream_eval.py --split test` (MAE в потоке 42.2 с),
  `python tools/bench_latency.py` (latency инференса)
- **Надёжность:** `docker compose stop replay` — система живёт на последних данных
  без падения; `start` — восстанавливается. Сабмит: `data/gt/submission_final.csv`.

## Инструкция для жюри

1. `docker compose up --build` — поднимаются три модуля: **ml-core** (:9201 NDTP +
   :8100 инференс), **backend** (:8000 API + WebSocket), **dashboard**; поток
   `replay` стартует автоматически (исторический датасет → живой NDTP).
2. Откройте **дашборд** http://localhost:8000/dashboard/index.html: карта маршрутной
   сети с ТС-стрелками (цвет = риск задержки), панель алертов-инцидентов слева
   (прогноз опоздания, причина, участок), What-if и чат в карточке ТС. Данные
   обновляются в реальном времени.
3. **Подать поток** можно тремя способами: replay идёт сам; живой эмулятор
   организаторов (см. «Запуск»); второй инстанс replay с другой скоростью/окном.
4. **Прогнозы и метрики:** `python tools/stream_eval.py --split test` — потоковый
   прогон по labels_test (MAE 42.2 с); `python tools/bench_latency.py` — latency

   PyDoc: http://localhost:8000/pydoc/index.html (на живом стенде:
   https://mt-hackathon-team-entropy.cloudpub.ru/pydoc/index.html).

## Архитектура

```
эмулятор NDTP / replay ──TCP 9201──► [ML-CORE: NDTP-сервер + фичи + CatBoost] :8100
                                              │  /internal/*
[BACKEND FastAPI] :8000 ◄─────────────────────┘
   ├─ /snapshot /alerts /routes /whatif /health, WS /ws (2 с)
   └─ BI-дашборд (MapLibre) /dashboard
```

### ML-ядро (ml-core)

NDTP-сервер → бинарный парсер → онлайн-фичи → CatBoost → предсказания для каждого ТС.

- **Задача:** регрессия задержки `target_delay_s` на целевую остановку — первую с
  планом в окне (T+10; T+15] мин. Горизонт соблюдается и офлайн, и на потоке.
- **Модель:** CatBoostRegressor (MAE-loss, 3000 итераций, lr 0.05, depth 6, seed 42),
  ~69 признаков: собственная GPS-оценка отклонений от расписания (est_dev_*),
  скорости/пробеги/простои в окнах 5–30 мин, контекст рейса, приоры остановок
  (LOO из фактов train-расписания), время суток. Анти-утечка: только
  `event_time ≤ T`, validate модели не виден.
- **Метрики:** офлайн-сабмит MAE **40.9 с** (скор 1.0); стриминг-модель без подсказки
  `cur_dev_s` — **42.2 с в потоке**; zero 103.3, baseline 93.4; latency инференса
  **8.7 мс/ТС** (p95 13.1).
- **Дополнительно внутри ядра:** HMM-матчинг телеметрии на OSM-граф
  (leuvenmapmatching) — точнее отклонения + «участок застревания»; ONNX-экспорт
  деплой-модели; GPS-гигиена (телепорты датасета отфильтровываются).

### Backend (FastAPI, :8000)

Оркестрация и API: `/snapshot`, `/alerts`, `/routes`, `/whatif`, `/health`,
WebSocket `/ws` (пуш каждые 2 с), раздача дашборда, Swagger `/docs`.

- **Алерты-инциденты:** ТС с высоким прогнозом опоздания — время, причина
  (простой/сгущение), «участок застревания» (улица из HMM-привязки), рекомендация.
- **What-if:** ползунки «доп. ТС на линию» (сжатие интервала → снятие до 35 % части
  прогноза) и «сокращение стоянок» (сек × остановок впереди) — сценарий считается
  для каждого ТС и агрегируется по парку.
- **Надёжность:** реконнект потока, работа на последнем известном состоянии,
  деградация карты при недоступности CDN (Carto → OpenFreeMap → автономный стиль).

### Фронтенд (dashboard)

Стек: MapLibre GL JS + vanilla JS, WebSocket, без фреймворков.

- Карта маршрутной сети: нитки по улицам OSM, остановки с адресами;
- ТС — стрелки по курсу движения, цвет = риск задержки (зелёный/жёлтый/красный),
  плавное движение (интерполяция + инерция между снапшотами);
- Карточка ТС по клику: план/факт-отклонение/прогноз + чат «диспетчер → водитель»;
- Панель инцидентов и What-if с эффектом по парку; real-time обновление.

## Модульность и производительность

Три независимых модуля в Docker поднимаются одной командой; связь — только по сети
(TCP NDTP + HTTP/WS), един состояние в ml-core. Дообучение — готовый офлайн-контур
`tools/gt_*` (фичи → обучение → стрим-модель → ONNX); инференс масштабируется
горизонтально (stateless-обработка потока).

Производительность (`tools/bench_latency.py`, CPU): предсказание **8.7 мс/ТС**
(p95 13.1), полный цикл парка **88 мс** (p95 92.6) при лимите 1–2 с; очередь не
накапливается; холодный старт — секунды (компактный кэш OSM-графа загружается за ~1.3 с).

## Дополнительные фичи (все пункты ТЗ + сверх)

1. **Map Matching по OSM** — нитки маршрутов по реальным улицам + HMM-матчинг
   телеметрии (уточнение отклонений, участок застревания);
2. **What-if анализ** — выпуск резервных ТС и сокращение стоянок с оценкой эффекта;
3. **Оптимизация инференса** — ONNX-экспорт: одиночный инференс 0.63 мс против
   4.9 мс нативного (**7.7×**), эквивалентность предиктов 1.7e-4;
4. **Ансамбль CatBoost + PyTorch GRU** — полный контур (обучение последовательностей,
   грид-поиск веса); поиск выбрал чистый CatBoost — решение принято данными;
5. Сверх ТЗ: стрелки по курсу с плавным движением, остановки с адресами, мок-чат
   «диспетчер → водитель», GPS-гигиена телеметрии, рибон хакатона.
